# 업무 자동화 봇 수익화 플레이북

'시간당 단가'가 아니라 '해결한 문제의 가치'로 청구하기 위한 실행 문서.
기술 문서는 [botkit.md](./botkit.md), 이 문서는 **무엇을 팔고 어떻게 납품하는가**만 다룬다.

핵심 전제: MVP 외주가 "요구사항대로 집을 새로 짓는 일"이라면, 이 상품은
"이미 지어둔 조립식 주택의 벽지(프롬프트)만 바꿔 납품하는 일"이다. 그래서
납품 1건에서 새로 작성하는 파일은 `config/jobs/<고객사>.yaml` 한 장이어야 한다.
파이썬을 열어야 한다면 그 건은 표준 등급이 아니다.

---

## 1. 무엇을 파는가

고객은 '웹사이트'나 '크롤러'를 원하는 게 아니라 **퇴근 시간을 앞당겨줄 직원**을 원한다.
서비스 제목부터 그렇게 바꾼다.

| | 문구 |
| --- | --- |
| ❌ 이전 | "원하시는 웹/앱 MVP, 크롤링 프로그램 개발해 드립니다" — 단가 경쟁, 요구사항 무한 확장 |
| ✅ 이후 | "매일 2시간 걸리는 엑셀/데이터 수작업, 맞춤형 AI 텔레그램 봇으로 자동화해 드립니다" — 가치 기반, 범위 고정 |

타겟은 AI에 익숙하지 않지만 매일 반복 수작업에 지친 **소상공인 / 1인 기업 / 마케터 / CS 담당자**다.

### 바로 팔리는 상품 3종 (전부 예시 잡으로 들어 있음)

| 상품 | 대상 | 잡 파일 | 소스 |
| --- | --- | --- | --- |
| 키워드 모닝 브리핑 | 마케터, 브랜드 담당 | `config/jobs/example_keyword_brief.yaml` | 뉴스 RSS |
| CS 답변 초안 자동 작성 | 쇼핑몰 CS | `config/jobs/example_cs_reply_draft.yaml` | 구글 시트 |
| 경쟁사 랭킹/리뷰 변화 알림 | 커머스 셀러 | `config/jobs/example_competitor_watch.yaml` | 고객사 JSON API |

세 파일 모두 `enabled: false`로 꺼둔 상태다. 복사해서 고객 이름으로 바꾸고 켜면 된다.

## 2. 가격 정책

개발비만 받고 끝내지 않는다. **유지보수 구독이 실제 수익의 본체**다.

### Standard — 50만 ~ 80만 원

- 구성: 시트/RSS(입력) → GitHub Actions(스케줄) → Claude(처리) → 텔레그램(알림)
- 작업: 잡 YAML 1장 작성 + 프롬프트 튜닝 + Secrets 연동. **실작업 1~2시간**
- 범위 고정 문구: "수집 소스 1종, 보고 채널 1개, 스케줄 1종"

### Deluxe — 150만 ~ 200만 원

- 구성: 고객사 기존 시스템 연동(슬랙 웹훅, 자체 어드민 API, Apps Script 웹앱)
- 작업: `http_json` 소스 + `webhook` 싱크 설정, 스키마 맞추기. **실작업 반나절~하루**
- 비공개 구글 시트 되쓰기는 이 등급의 **후속 개발(P1-1)** 이다. 현재 `http_json`은
  읽기 경로이고, 행별 쓰기·파싱 실패 폴백은 아직 제공하지 않는다.

### Premium — 월 10만 ~ 30만 원 (구독)

- 제공: 서버/스케줄 관리, API 토큰 관리, 프롬프트 주기 업데이트, 장애 대응
- 구현된 운영 도구: P0-1 월별 JSONL 실행 이력과 `botkit report --month YYYY-MM` 원가 집계.
  고객별 시크릿 격리(P0-2)·승인 모드(P0-3)는 아직 미구현이며 완료 기능으로 판매하지 않는다.
- 셀링 포인트: "개발을 모르시니 제가 알아서 관리해 드립니다"
- **10곳만 구독해도 월 100~300만 원**이 개발 없이 발생한다

### 구독 수익의 원가 (직접 계산해둘 것)

Claude Opus 5 기준 $5/100만 입력토큰, $25/100만 출력토큰. 환율 1,400원 가정.
단가의 실행 기준은 `config/pricing.yaml`이다. 아래 예산 예시는 실측 정산이 아니며,
실제 원가는 `botkit report`와 API 청구서를 대조한다. dry-run/발송 실패 비용도 포함하고
`unknown`(응답 유실 등)이 있으면 그 비용을 추가 확인한다. [계측/백업 안내](./botkit.md#7-월별-비용-계측).

| 잡 | 1회 토큰(입력/출력) | 1회 비용 | 월 비용(평일 기준) |
| --- | --- | --- | --- |
| 뉴스 브리핑 1일 1회 | 약 6천 / 3천 | 약 150원 | 약 3,300원 |
| CS 초안 1일 3회 | 약 4천 / 5천 | 약 200원 | 약 13,000원 |

GitHub Actions는 퍼블릭 리포지터리 무료, 프라이빗도 월 2,000분 무료다. 매시
실행(월 720회 × 1분 내외)은 무료 한도 안에 들어온다.

즉 **원가 월 5천~2만 원 수준에 10~30만 원을 청구**하는 구조다. 고객이 지불하는
것은 토큰이 아니라 '신경 쓰지 않아도 되는 상태'다. 단, 아래 두 경우 원가가 급등하니
견적 전에 확인한다.

- 수집 건수가 많고 본문이 긴 경우(`source.limit`, `summary_chars`, `max_input_chars` 확인)
- 실행 빈도가 시간당 단위로 잦은 경우

비용을 낮춰야 하면 모델을 바꾸기 전에 `prompt.effort: low`부터 시도한다.
같은 모델에서 토큰 사용량만 줄이는 쪽이 품질 저하 위험이 작다.

## 3. 납품 파이프라인 (주문 → 2시간)

| 단계 | 시간 | 하는 일 |
| --- | --- | --- |
| 1. 온보딩 | 10분 | 구글 폼 발송 → 현재 수작업 절차 / 원하는 결과 포맷 / 수신 텔레그램 확보 |
| 2. 잡 생성 | 10분 | `cp config/jobs/_TEMPLATE.yaml config/jobs/<고객사>.yaml`, Secrets 등록 |
| 3. 프롬프트 튜닝 | 30분 | `prompt.system`에 고객 업무 규칙(응대 매뉴얼, 금칙사항)을 옮겨 적는다 |
| 4. 리허설 | 20분 | `botkit validate` → `botkit test-telegram` → `botkit run --job X --dry-run` |
| 5. 인도 | 20분 | 실제 1회 발송, 고객 채팅방에서 결과 확인, 사용 안내 |

### 온보딩 폼에서 반드시 받아야 하는 6가지

1. 지금 그 일을 **어떤 순서로** 하는지 (화면 녹화 1분이면 더 좋다)
2. 결과물을 받고 싶은 **시각과 요일** → `schedule`
3. 데이터가 있는 곳 (시트 링크 / 뉴스 키워드 / API 문서) → `source`
4. **하면 안 되는 말** (할인 확약, 일정 약속 등) → `prompt.system`의 금칙사항
5. 수신 텔레그램 (개인 or 팀 그룹) → `TELEGRAM_CHAT_ID`
6. 예시 결과물 1개 — "이런 식으로 나오면 됩니다" 샘플이 프롬프트 품질을 가장 크게 좌우한다

### 납품 전 반드시 합의할 3가지 (분쟁 예방)

- **API 키 명의**: 고객 명의로 발급받아 고객이 직접 결제할지, 내 키로 쓰고 구독료에
  포함할지. 후자라면 사용량 급증 시 상한을 계약서에 적어둔다.
- **데이터 처리 동의**: CS 문의처럼 고객명·연락처가 섞인 데이터를 외부 API로
  보내는 경우, 고객사로부터 처리 동의를 문서로 받아둔다. 개인정보가 꼭 필요하지
  않은 잡이라면 공유용 시트에서 해당 열을 아예 뺀다. `fields`는 HTTP JSON 소스의 열 선택이며,
  시트의 `where_equals`는 행 필터이므로 개인정보 열을 제거하지 않는다.
- **자동 발행 금지선**: 이 봇은 **초안을 사람에게 보내는 것**까지만 한다.
  고객 명의로 외부에 자동 게시·발송하는 기능은 별도 계약 없이 넣지 않는다.

### 구독 계약서에 넣을 범위

- 포함: 스케줄/서버 관리, 토큰 갱신, 월 1회 프롬프트 튜닝, 장애 대응(영업일 1일 내)
- 제외: 신규 수집 소스 추가, 신규 채널 추가, 보고 형식 전면 개편 → 별도 견적
  (이 선이 없으면 구독료를 받으면서 무한 개발을 하게 된다)

## 4. 오늘 할 일

1. **포트폴리오 영상 1분 촬영 — 가장 중요.** 구글 시트에 문의 몇 줄을 적고,
   잠시 뒤 텔레그램에 정리된 답변 초안이 "띠링" 도착하는 과정을 화면 녹화한다.
   고객은 코드를 보지 않는다. 이 결과 화면을 보고 산다.
   - 촬영용 실행: `botkit run --job <잡> --dry-run`으로 먼저 문구를 다듬고,
     본 촬영은 실제 발송으로 한다.
2. **상세페이지 개편.** "이런 분께 추천합니다"를 구체적인 장면으로 쓴다 —
   "매일 아침 경쟁사 순위를 엑셀에 옮겨 적는 분", "같은 CS 답변을 하루 30번 쓰는 분".
3. **예시 잡 3개를 내 계정으로 실제 가동.** 내 브랜드 키워드로 모닝 브리핑을
   한 달 돌리면 그 자체가 포트폴리오이자 프롬프트 튜닝 연습이 된다.
4. **운영자 알림 채널 먼저 만들기.** `OPS_TELEGRAM_CHAT_ID`를 등록해두면 고객보다
   먼저 장애를 안다. 구독 상품의 신뢰는 여기서 갈린다.

> 외주 플랫폼을 통해 판매하면 플랫폼 수수료가 붙고, 월 구독은 플랫폼 밖 정기
> 결제로 빠지는 경우가 많다. 1건 납품 시 실수령액과 구독 정산 방식은 판매 전에
> 각 플랫폼의 현행 수수료 정책을 직접 확인해서 가격에 반영할 것.
