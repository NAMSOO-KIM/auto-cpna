## KNOWN ISSUES / 판단 지점

- 공용 폴백은 기존 운영 호환성을 위한 요구사항이다. 전용 토큰이 삭제되면 공용으로
  돌아가고, 토큰/채팅 ID가 각각 폴백할 수 있다. validate는 이를 숨기지 않는다.
- 이 기능은 `__CLIENT_ID` namespace의 참조 격리다. 공용 별칭에 다른 고객 값을
  넣거나 운영자가 YAML client_id 자체를 바꾸는 상황까지 OS 수준으로 격리하지 않는다.
- 고객사 1곳 = 저장소 1개를 권장한다. 다중 고객은 공용 API 한도·설정 로딩·러너·상태
  저장 장애가 전파될 수 있다. 고객은 저장소/프로세스 환경에 접근하는 주체가 아니다.
- ANTHROPIC_API_KEY와 운영자 알림은 기존 공용 설정이다. 전용 토큰만 설정해도
  운영자 알림용 공용 TELEGRAM_BOT_TOKEN/OPS_TELEGRAM_CHAT_ID는 별도로 준비해야 한다.
- 새로운 고객 이름의 환경변수를 GitHub Secrets에만 넣으면 안 된다. .env.example과
  workflow env에도 이름을 매핑해야 한다. Python 변경이나 새 코드 파일은 필요 없다.
- 이력/중복 방지 상태 형식과 기본 경로는 변경하지 않았다. 이력 분리는 YAML로 선택한다.

## ROLLBACK PLAN

운영 적용 전에는 지정 브랜치 코드만 변경됐다. 운영 적용을 승인받아 진행한 뒤 롤백이
필요하면 새 실행을 멈추고 잡 YAML·상태·장부·환경변수 이름 매핑을 백업한다.
P0-2 기능 커밋을 revert한 후 client_id가 없는 이전 YAML과 이전 시크릿 매핑을 함께
복원한다. 전용 키만 사용하는 상태에서 코드만 되돌리면 공용 키가 없어 실행 실패가
발생하므로 코드/설정의 버전을 맞춘다. 상태·장부는 삭제하거나 자동 이전하지 않는다.
사용자 승인 후 테스트/validate와 데모 수신을 확인하고 스케줄을 재개한다.
